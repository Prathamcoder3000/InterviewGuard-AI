# InterviewGuard UI

The interview recorder extends the established results dashboard for candidates and hackathon demo users. Preserve the current enterprise visual language: slate-50 canvas, white panels, slate-200 borders, blue-600 primary actions, rounded-xl panels, system sans text and monospace timers. Existing dashboard classes and app/globals.css own runtime styling; no new global tokens are introduced.

Reuse components/ui/button.tsx for actions. Keep live video as the main surface, with instructions and technical status alongside it at desktop widths and stacked on mobile. Live preview stays muted and mirrored; playback has native accessible controls and is not mirrored.

Interview surfaces keep white/slate secondary actions in both OS color schemes through the shared interview-outline Button variant. The AI interviewer owns separate consent for Groq resume/answer/audio processing; optional answer transcription must not contradict the local-only video and face-reference notices. Question playback stops before microphone answer capture. Transcripts remain editable and require explicit submission.

Consent precedes device access. Permission requests are cancellable. Recording completion releases all devices. Retake discards local media. Recording bytes and object URLs live only in the mounted interview experience. Demo results remain explicitly separate from recording observations; face count, approximate orientation, and consented reference-photo similarity are local observations; no trait, emotion, fraud, or hiring inference is performed.

Analysis uses three separate dimensions: supported positive answers, negative answer-content criteria, and possible external assistance. Communication observations have no score contribution. The review priority rubric assigns 25 points per supported negative criterion, with coverage visible and missing evidence marked Not evaluated. This is a transparent demo index, not a calibrated fraud probability or hiring recommendation. analysis-policy.ts owns the rule allowlists and display-boundary normalization. Do not trust legacy behavioral scores or turn video/voice style into emotion, honesty, identity, or competence inference.

Evaluator workspace keeps completed candidate analyses in page memory with stable IDs, preserving intake state across navigation tabs. Refresh or leaving the page clears this session; no resume or answer data is persisted to browser storage. Candidate selection is manual, with search, role/source filters and optional ascending technical review index sorting. No automatic hiring selection is performed. The backend technical index (60/25/15 weights, missing evidence may contribute) is separate from the sample report’s 25-point evidence rubric. Charts count claimed skill assessments once; unknown/missing assessments remain Not evaluated. Mock analyses are labeled per candidate. Face and delivery observations never enter candidate charts or sorting.
